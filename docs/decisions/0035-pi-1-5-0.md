# 0035. Pi 1.5.0

## Status

Accepted, 2026-11-03. Amends [0012](0012-terminal-ui.md) (the chat is built from conversation views, not events).

## Context

Persistence pinned every Pi package at 1.3.0. The packages it brings in carried known vulnerabilities (`undici`,
`minimatch`), first lifted with npm `overrides`, and Pi had moved on two releases. Pi 1.5.0 breaks the API in ways
this host uses:

- `watchEvents()` and its event types are gone: a renderer reads a conversation's state (`Conversation.watch()`,
  `pi.live`) instead of assembling it from events.
- Tool schemas are JSON Schema through `@earendil-works/pi-schema`; pi-ai no longer exports TypeBox's `Type`.
- Documents need a `checkpointWhen` policy, `ToolExecutionApi` has `now`, `FileChange` replaces the env's
  `WatchChange`, and watch listeners take one change object.
- Opening a SQLite storage migrates it to Durable schema version 2 (since 1.4.0). A migrated chat cannot be opened by
  1.3.0.

## Decision

- Pin every Pi package at 1.5.0, `@earendil-works/pi-schema` included, as direct dependencies. Keep the `undici` and
  `minimatch` overrides while Pi's own pins are older than their fixes. Chord 1.5.0 asks for `ws` 8.21.0 as an optional
  peer; an override gives it the `ws` 8.22.0 the server already pins.
- The terminal UI's feed watches the conversation view and `pi.live` and produces the same `ChatItem`s as before;
  `src/ui/types.ts` and the wire protocol are unchanged.
- Every tool keeps its name and its exact JSON Schema: TypeBox's open objects become `obj(…, { open: true })`, its
  closed ones `obj(…)`, and string literals keep `type` with `const`.
- `agents.registry` checkpoints every 64 deltas, as Pi's own code mode document does; the routing documents never
  checkpoint (`() => false`), which keeps their 1.3.0 behaviour.
- The migration of `chat.sqlite` is accepted as one way. The operations guide says to back up first.
- `settings.restartLimit` is `Infinity`. Since 1.4.0 a task cut off by crashes 5 times in a row ends instead of
  running again, which would drop an `agents.deliver` message and break exactly-once delivery (ADR 0006); without a
  limit a task runs again after every crash, as under 1.3.0. A model request in flight at a crash still counts as a
  failed attempt under Pi's retry policy, so a generation does not loop.

## Consequences

- Rolling back past this release means restoring a backup taken before it.
- A withdrawn queued message no longer shows "Queued message withdrawn.", and failures of other task kinds no longer
  show a notice: Pi 1.5.0's view has no event for them. Run failures and compaction failures still show.
- Partial answers and running tool output are stored later than they are shown (Pi's deferred progress commits), so a
  crash may lose up to a second more of a partial answer; the finished answer is stored as before.
