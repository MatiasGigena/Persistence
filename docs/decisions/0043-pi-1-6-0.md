# 0043. Pi 1.6.0

## Status

Accepted, 2026-11-24. Follows [0037](0037-pi-1-5-2.md), whose decisions stand except where this one says otherwise.

## Context

Pi released 1.6.0 on 2026-11-20. For this host:

- pi-durable: a tool's `execute()` may return a `ToolPark` (`sleep` or `wait`) instead of a result, and
  `ToolExecutionApi` gains `wake`, `checkpoint` and `readSignal()`. Wrappers never park on their own. Code-mode
  namespaces now come from `Extension.namespace` (this host's `codemode` kit never used the removed prefixes).
  `RunEndTask` is renamed `HookTask` (unused here). `pi.tool` is task version 4 and `pi.generation` version 3.
- pi-durable fixes: `Submission.wait()` and `waitForTask()` no longer leave an unhandled rejection when the Harness
  closes mid-wait, and task changes deep in an ownership chain no longer cost O(n²).
- `read` no longer stores a "does not support images" note in the result, which the model kept reading after a switch
  to a vision model; a text-only model is named in `details.imageUnsupportedByModel` instead.
- pi-tui: `render()` returns `readonly string[]`, and the alternate-screen TUI reuses every component's last output
  when a frame only moves the viewport (a scroll or a selection), so a long transcript is not rendered again on every
  wheel event.
- pi-ai's catalog adds GPT-6.2 Astra and GPT-6.2 Sol; the prices of the models this host defaults to are unchanged.
- Chord's optional peer dependencies are ranges (`ws` `^8.21.0`), not exact versions.

## Decision

- Pin every Pi package at 1.6.0 and move `SDK` with them.
- Drop the `ws` override of ADR 0035: Chord's range takes the `ws` 8.22.0 the server already pins. The global
  `minimatch` override stays (pi-coding-agent still pins 11.0.3).
- The machine executor (`src/client/machine-executor.ts`) runs the coding tools once, outside any Harness: its api
  has no wake or checkpoint, refuses `readSignal()`, and turns a park into a tool error. The coding tools never park.
- The terminal UI's scroll view (`ChatScroll` in `src/ui/tui/app.ts`) asks for a full render when the chat starts
  or stops following its end, since the footer's "more below" mark is the one output that depends on the scroll
  position. Scrolling within the chat still reuses the last output.
- The host's default model moves from `openai-codex/gpt-6.1-sol` to `openai-codex/gpt-6.2-sol`, Codex's new default:
  the same price, context window (500k), image input and thinking levels. A model saved with `/model` or set in
  `PI_DURABLE_MODEL` still wins.
- The built-in roster's Reviewer and Researcher (`src/agents/roster.ts`) move to `openai-codex/gpt-6.2-sol` too, at
  their own thinking levels. `syncAgents` re-derives the standing agents at every work launch, so existing ones
  follow; a custom `settings.json` roster keeps the models it names.

## Consequences

- **One-way for rollbacks:** a chat that 1.6.0 opened holds tool and generation tasks at the new versions. A 1.5.2
  checkout still opens it (the Durable SQLite schema is still version 2), but blocks those tasks (`task_too_old`) and
  takes a sleep without `until` as due. Roll back by restoring a backup taken before the update.
- Tool results written from now on measure `durationMs` from the tool task's first run, parks and reruns included.
- No persisted name changes.
